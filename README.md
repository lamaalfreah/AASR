# Arabic Adaptive Spatial Reasoning (AASR)

AASR is an adaptive reasoning framework for Arabic spatial questions over long-context data.

The current system uses **Router V2** to dynamically route each query between a lightweight **BiGRU-based Short path** and a **Qwen3-4B Long-context path**.

The selected reasoning path produces a **Structured Query**, which is then passed to the **Geo Engine** for deterministic spatial execution and final answer generation.

---

## Current Architecture

```text
                         User Question
                               |
                               v
                           Router V2
                         /           \
                        /             \
                       v               v
                Short Path        Long-Context Path
                  BiGRU              Qwen3-4B
                       \               /
                        \             /
                         v           v
                      Structured Query
                             |
                             v
                         Geo Engine
                             |
                             v
                       Spatial Answer
                             |
                             v
                      Django Application
```

### Main Components

- **Router V2** — selects the appropriate reasoning path for each query.
- **Short Path — BiGRU** — handles queries that can be processed efficiently using the lightweight trained BiGRU model.
- **Long-Context Path — Qwen3-4B** — handles queries requiring more complex or long-context reasoning.
- **Structured Query** — provides a normalized representation of the spatial task that can be executed deterministically.
- **Geo Engine** — interprets and executes the Structured Query using spatial parsing, normalization, entity resolution, geometry, and spatial operations.
- **Django Application** — provides the API and frontend integration layer.

### Routing Architecture

```text
                Question
                   |
                   v
               Router V2
               /       \
              /         \
             v           v
          BiGRU       Qwen3-4B
          Short         Long
             \           /
              \         /
               v       v
             Structured
                Query
```

Router V2 allows AASR to avoid sending every query through the same reasoning strategy.

The goal is to select the reasoning path that best matches the query while balancing:

- reasoning quality
- latency
- token usage
- model-resource usage
- query complexity

## Geo Engine

The Geo Engine is implemented under:

```text
spatial/
```

It receives the **Structured Query** generated by the selected reasoning path and performs the spatial execution required to produce the final answer.

### Geo Engine Responsibilities

- context parsing
- structured-query validation
- normalization
- entity resolution
- coordinate handling
- geometry calculations
- spatial relationship computation
- query execution
- structured answer generation

### Key Files

```text
spatial/schema.py
spatial/query_parser.py
spatial/context_parser.py
spatial/normalization.py
spatial/identity.py
spatial/geometry.py
spatial/executor.py
```

The high-level reasoning flow is therefore:

```text
Question
   |
   v
Router V2
   |
   +------ Short Path: BiGRU
   |
   +------ Long Path: Qwen3-4B
   |
   v
Structured Query
   |
   v
Geo Engine
   |
   v
Final Spatial Answer
```

# AASR Frontend

AASR uses a Django-based single-page interface.

The latest frontend baseline comes from the current `main` branch.

The active model/UI integration work is being developed on:

```text
integration/router-v2-ui
```

The goal of the current integration stage is to connect the latest Django interface directly to the Router V2 reasoning architecture.

## Local Django Setup

```bash
python -m venv .venv
source .venv/bin/activate        # macOS / Linux
# .venv\Scripts\activate         # Windows

pip install -r requirements.txt
python manage.py migrate
python manage.py runserver
```

Then open:

```text
http://127.0.0.1:8000/
```

Some reasoning paths require additional provider credentials or remote Modal infrastructure.
